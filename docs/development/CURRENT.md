On 2026-10-20, the maintainer also reported both the Duo dual-row visual style and B1136 three-finish MIUIX glass visually satisfactory. - **Typography:** [#617](https://github.com/CHS-Haple/Guiyuan/pull/617) draws battery digits and network type (including 5GA) using native `wght` requests **200–1000**, 50-point user steps, default 600, and no synthetic glyph outlines. The renderer retains a separately captured native CC target, independent of the user minimum. Legacy saved values are clamped by visual bank; strict V1 backup import maps only historical 1001–1400 integer values to 1000. The current system font may produce the same outline for several requested weights. [#615](https://github.com/CHS-Haple/Guiyuan/issues/615)'s 400–1400 optical-thickness research target was superseded, not universally solved.
- **Runtime dependency:** AndroidX Core 1.19.1 was integrated through [#628](https://github.com/CHS-Haple/Guiyuan/pull/628), with notices and B1112 Build identity updated. `NativeVectorStroke` calls `androidx.core.graphics.PathParser` inside the SystemUI indicator path for non-default Wi-Fi/airplane stroke weights; unsupported native vector input falls back to the original SystemUI Drawable. The accepted scope is the pinned target and focused initial device feedback, not bytecode equivalence across Core releases or universal compatibility.
- **Companion/UI:** [#600](https://github.com/CHS-Haple/Guiyuan/pull/600) pins all five MIUIX Android modules to `0.9.4-8972f941-SNAPSHOT`. [#645](https://github.com/CHS-Haple/Guiyuan/pull/645) replaces the direct Backdrop/Shapes binary dependencies with MIUIX Blur and attributed upstream optical helpers; its liquid finishes are Blur 8 dp / 40%, Balanced 4 dp / 40%, and Clear 2 dp / 30%, all using 24 / 24 dp rim refraction. The 4 dp preset now stores `"Balanced"`; earlier `"Default"` and `"Blur"` values still decode to Balanced, and the 8 dp preset still stores `"Blur8"`. The app retains its own Insets listener using `LocalDisplayCutoutFixEnabled`; removed Spec2026 choices resolve to Spec2025 without rewriting old prefs. Preview Sandbox never writes simulated data to SystemUI.
- **Backup/configuration:** V1 export/import contains feature preferences, independent single/dual × layout visual profiles and custom battery schemes, but excludes unrelated Settings and Preview/Sandbox state. Both export and import require document-provider `content://` URIs; import enforces bounded UTF-8/JSON validation. Failed feature writes restore the original feature-owned key presence and change timestamp, along with existing visual rollback. Custom scheme names are normalized at their repository read/write boundary so previously saved unsafe text cannot poison new exports; external V1 imports remain strict and reject noncanonical names. Imports also reject contradictory mode-wide values across the two layouts of one SIM mode without coupling single and dual preferences. This is compensating rollback across two preference stores, not a cross-store atomic transaction. Do not widen import formats, alter profile semantics or add shared preferences writes for UI simulations without separate validation.

## Presentation ownership and lifecycle

- Home projects the combined indicator while surrounding native slot layout remains SystemUI-owned. Keyguard/AOD use one host-scoped family; AOD never becomes a CC transition source. Full Control Center remains native. The optional dual-row mobile presentation requires two verified subscriptions and complete SIM-slot identity; ambiguous or missing inputs use the existing single/native-safe fallback without clearing the saved preference.
- Partial CC transitions use verified native FAKE/FINAL endpoints, measured native peers and retained native typography where available. Compound-row shape morphing requires optically verified rows and does not independently assert a row's SIM ownership. Charging changes retarget the existing reservation writer. Do not mutate native FINAL view layout, visibility, alpha or translation to hide alignment errors.
- `SysUiPresentationOwner` owns limited masking/reservations; CC Session owns its temporary projection and observer registration. Invalidation checks native bind, direct root changes, slot/optical ancestry and configuration, with observer cleanup on the registration-time `ViewTreeObserver` and any distinct live observer. Avoid per-frame tree probes or unbounded polling.
- API 102 Hot Reload uses neutral V10 transfer data and main-thread retirement of old view/listener owners before accepting a new generation, then validates the host/hook before reacquiring presentation. Older V9 owners require a one-time SystemUI restart when crossing the migration boundary. Native icons may appear briefly during an unavoidable inter-generation gap; no frame-atomic handoff is claimed.
- Feature and visual preference callbacks are generation-gated and must not retain a binding lock while the framework owns its callback lock. App settings UI, snackbar, sheets and previews retain their existing MIUIX/Compose ownership.

## Open compatibility and maintenance questions

- [#519](https://github.com/CHS-Haple/Guiyuan/issues/519): exceptional LSPosed 7927/API 102 retirement or unregister failures remain compatibility debt, **not** an observed baseline regression. Normal Hot Reload passed focused device checks. Do not restore rejected old-loader bridges or retry/timer hacks; investigate failure behavior only with authoritative contracts or reproducible evidence. [7927 evidence](../reference/lsposed-7927-hot-reload.md).
- LSPosed 7930 archive is only statically documented; its runtime injection and reload paths are not validated on this device. [7930 evidence](../reference/lsposed-7930-compatibility.md).
- [#651](https://github.com/CHS-Haple/Guiyuan/pull/651) is an **unaccepted dynamic mobile-font-axis experiment**. It reads `fvar` only when the live native `MobileTypeDrawable` Typeface is identical to its known file-backed system Typeface, and reports a bounded range through an explicitly targeted, system-UID-authenticated Android broadcast. Other font branches do not inherit MiSans bounds; they keep the existing compatibility slider. Native-family identity, companion reporting, changed visual presets, input safety and device/performance impact require test before merge.
- Other HyperOS/SystemUI fonts, dual-SIM aggregation variants, and third-party-modified view trees still need their own verification. [#646](https://github.com/CHS-Haple/Guiyuan/issues/646) separately tracks reported 5GA suffix spacing growth above network text weight ~650; diagnose the exact font's ink/advance layout before changing any gap constant. Cached native geometry cannot guarantee detection of silent descendant replacement without a native event.
- Short, conditionally expanded Settings lists can have scroll-position edge cases; menu-to-modal timing remains upstream MIUIX-owned absent a concrete reproducible defect. [#521](https://github.com/CHS-Haple/Guiyuan/issues/521) was closed after the verified native-slot and observer fixes.
